# T-005 Hapus fitur contoh notes

## Status

Selesai. Semua kriteria otomatis terpenuhi dan verifikasi manual dikonfirmasi user di Chrome. Branch: `chore/t-005-remove-notes`.

## Ringkasan

Mengikuti panduan "Menghapus fitur contoh notes" di `docs/conventions.md`:

1. **API:** `src/features/notes/` dan `src/db/schema/notes.ts` dihapus, beserta ekspor di `schema/index.ts` dan wiring di `src/app.ts`. Migrasi baru `drizzle/0004_drop_notes.sql` (`DROP TABLE "notes" CASCADE;`); migrasi lama tidak disentuh.
2. **Test API:** `test/unit/features/notes/`, `test/int/notes/`, `insertNote`/`insertNotes` di `factories.ts` dihapus; `notes.created_at` di `schema.int.test.ts` diganti `shopping_items.created_at`. Komentar yang merujuk notes (`pagination.ts`, `shopping-items.ts`, `all-routes-require-auth.int.test.ts`) diperbarui.
3. **Kontrak:** `pnpm contract:generate` menghapus `NotesClient` dan model notes dari `openapi.json` dan `api_client`; `packages/contract/dart/test/api_client_test.dart` kini memakai `ShoppingClient` dan model shopping.
4. **Flutter:** `lib/features/notes/` dan `test/features/notes/` dihapus, beserta `registerNotesDependencies`, rute notes, dan bagian notes di test DI, router, `auth_interceptor_test`, `error_mapper_test`. `AppRoutes.home` sudah mengarah ke `/shopping` sejak T-004.
5. **Dokumen:** semua rujukan file contoh notes di `docs/conventions.md` diganti file shopping yang setara; bagian "Menghapus fitur contoh notes" dihapus. `README.md` dan `CLAUDE.md` (bagian "Fitur contoh") kini menyebut shopping sebagai contoh.
6. **Penjaga konvensi dipindahkan:** dua test yang dirujuk konvensi hanya ada di notes, jadi dipindahkan ke shopping agar konvensinya tetap dijaga:
   - `shopping-items.int.test.ts` › tidak ada duplikat bila beberapa barang jatuh di milidetik yang sama (pagination, presisi timestamp).
   - `shopping_flow_test.dart` › kembali dari form tanpa hasil → halaman pertama dimuat ulang (jalur pertama "kembali ke daftar tanpa hasil").

### Langkah verifikasi manual

Persiapan: `.env` sudah ada (disalin user di T-004). `docker compose up -d --wait`, lalu `pnpm --filter api db:migrate` (menerapkan `0004_drop_notes` ke database utama), lalu `pnpm --filter api dev`.

1. Di `apps/app`: `flutter run -d chrome --web-port 8081 --dart-define-from-file=config/dev.json`.
2. Masuk (atau daftar) → halaman **Daftar belanja** tampil sebagai halaman utama.
3. Tambah satu barang, centang, ubah filter, lalu "Hapus yang sudah dibeli" → semuanya berjalan seperti di T-004.
4. Buka `http://localhost:8081/notes` → halaman **Halaman tidak ditemukan**.

## Keputusan yang diambil sendiri

1. **Bagian "Menghapus fitur contoh notes" dihapus dari `docs/conventions.md`**, karena fiturnya sudah tidak ada; langkahnya tercatat di log ini dan di `docs/template-build/`.
2. **`CLAUDE.md` bagian "Fitur contoh" diubah** agar menyebut shopping sebagai contoh. Tanpa itu, CLAUDE.md merujuk fitur dan bagian dokumen yang sudah tidak ada. Mohon ditinjau karena file ini mengatur cara kerja agent.
3. **Usulan konvensi dari T-004 dimasukkan ke `docs/conventions.md`** bersamaan dengan penggantian rujukan (seperti yang direncanakan di log T-004): filter di daftar berpagination, aksi di daftar dengan kegagalan sebagai SnackBar, dan teks kegagalan khusus fitur di field. Ditambah satu poin dari T-001: pelanggaran keunikan → error domain di repository → `CONFLICT` di use case.
4. **Konvensi form disesuaikan dengan shopping**, yang tidak punya `GET` per barang: `Loading`/`LoadFailed` dan `cubit.load(id)` ditulis sebagai varian untuk fitur yang punya `GET` per item, bukan dihapus.
5. **Konvensi "Waktu" (`formatMediumDate`) dipertahankan** dengan catatan belum dipakai fitur shopping; tidak ada lagi file contohnya.
6. **String `notes/...` dan `noteId` di test port dibiarkan**, sesuai panduan (hanya data contoh, bukan kode fitur).

Penyebab:  memakai profil Chrome yang tetap ada antar-run (), dan IndexedDB-nya masih menyimpan sesi login dari T-004. Akan terulang bila  dijalankan ulang dalam keadaan masih login.
