## Ringkasan

- Tabel `shopping_items` (migrasi `0003_shopping_items.sql`): `name` 1–80 karakter, `quantity` 1–999 default 1, `is_done` default `false`, FK ke `users` `ON DELETE CASCADE`, unique index `(user_id, lower(name))` untuk nama unik per user tanpa membedakan huruf besar dan kecil, dan index pagination `(user_id, created_at DESC, id DESC)`.
- Fitur `apps/api/src/features/shopping/` mengikuti pola notes: domain, empat use case (`list`, `create`, `update`, `delete`), repository Drizzle, dan route `GET/POST /v1/shopping-items` serta `PATCH/DELETE /v1/shopping-items/{id}`, dirakit di `src/app.ts`.
- Filter `status` (`all`, `open`, `done`; default `all`) lewat `PaginationQuerySchema.extend(...)`.
- Nama duplikat → `409 CONFLICT` (D-01) untuk tambah dan ubah nama.
- Kontrak di-generate ulang: `ShoppingClient`, `ShoppingItem`, `ShoppingItemPage`, `ShoppingItemStatus` (enum), `CreateShoppingItemInput`, `UpdateShoppingItemInput`.
- `POST /v1/shopping-items/clear-done` belum dibuat (T-002).

## Keputusan yang diambil sendiri

1. **Pelanggaran keunikan lewat error domain.** Repository menangkap SQLSTATE `23505` dengan constraint `shopping_items_user_id_name_unique` dan melempar `ShoppingItemNameTakenError` (didefinisikan di `domain/`); use case mengubahnya menjadi `AppError('CONFLICT', ...)`. Alasan: use case tidak boleh mengenal Drizzle/pg, dan cek "ambil dulu lalu insert" rawan balapan. Konvensi belum mengatur ini. **Usulan untuk `docs/conventions.md`** (bagian Clean Architecture API): "Keunikan ditegakkan constraint database bernama; repository memetakan `23505` dengan nama constraint itu ke error domain, use case mengubahnya menjadi `CONFLICT`. Contoh: `features/shopping/infrastructure/drizzle-shopping-item-repository.ts`."
2. **Unik tanpa membedakan huruf besar dan kecil** dengan unique index ekspresi `(user_id, lower(name))`, bukan kolom tambahan atau `citext` (tanpa extension). Nama disimpan sesuai ketikan user (setelah di-trim). Mengubah huruf besar-kecil nama sendiri tetap diizinkan.
3. **Filter `status` sebagai komponen OpenAPI bernama `ShoppingItemStatus`** agar client Dart mendapat enum, bukan `String`. Efek samping: `default: "all"` ikut tercatat di komponen enum (bukan hanya di parameter). Tidak berpengaruh ke client: parameter tetap opsional dan tidak dikirim bila `null`.
4. **Tidak ada `GET /v1/shopping-items/{id}`** karena tidak ada di kontrak PRD bagian 5.
5. **`quantity` harus integer JSON**: string `"2"` dan `1.5` → `422 details.quantity` (tanpa coercion pada body).
6. `test/int/db/schema.int.test.ts` dan `all-routes-require-auth.int.test.ts` tidak diubah, karena keduanya otomatis mencakup tabel dan route baru.
