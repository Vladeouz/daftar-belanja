### Langkah verifikasi manual

Persiapan (sekali): `.env` disalin user dari `.env.example`, `docker compose up -d --wait`, `pnpm --filter api db:migrate`, `pnpm --filter api dev`.

1. Chrome: di `apps/app`, `flutter run -d chrome --web-port 8081 --dart-define-from-file=config/dev.json`. Android: nyalakan emulator, lalu `flutter run -d emulator-5554 --dart-define-from-file=config/dev.json` (sesuaikan id perangkat dari `flutter devices`).
2. Daftar atau masuk → halaman **Daftar belanja** tampil sebagai halaman utama.
3. Tambah "Telur" (jumlah 2), "Susu", "Roti" lewat tombol +.
4. Tambah "telur" → pesan **"Barang ini sudah ada di daftar."** di bawah field nama.
5. Centang "Susu" → tercoret. Muat ulang (Chrome: F5; Android: tutup dan buka lagi aplikasi, atau ganti filter lalu kembali ke Semua) → "Susu" tetap tercentang.
6. Pilih **Belum** → hanya Telur dan Roti; **Sudah** → hanya Susu; **Semua** → ketiganya.
7. Tekan ikon **Hapus yang sudah dibeli** di app bar → dialog → **Hapus** → "Susu" hilang; tetap hilang setelah dimuat ulang.

## Keputusan yang diambil sendiri

1. **Form ubah tidak bisa dibuka lewat URL.** API tidak punya `GET /v1/shopping-items/{id}` (bukan bagian kontrak PRD), jadi `/shopping/:id` tanpa barang di `extra` (URL langsung, muat ulang di web) diarahkan ke `/shopping`. Tidak ada state `Loading`/`LoadFailed` di form. Alternatif bila diinginkan: tambah endpoint GET per barang (mengubah kontrak API).
2. **Pesan khusus CONFLICT di form** (`shoppingItemNameConflictMessage` di `shopping_item_form.dart`), bukan `failureMessage(FailureCode.conflict)` yang umum, karena FR-05 meminta teks tertentu di field nama. Teks tetap diturunkan dari `code`, bukan dari pesan server (D-03).
3. **Filter disimpan di state Cubit** dan setiap state membawanya, agar pilihan filter tetap tampil saat memuat atau gagal. Hasil permintaan lama dibuang lewat penghitung generasi (`_generation`) saat filter diganti atau daftar dimuat ulang; `load()` kedua untuk filter yang sama selagi memuat diabaikan (seperti notes).
4. **Centang dan "Hapus yang sudah dibeli" diterapkan ke daftar tanpa memuat ulang** (tidak optimistis: daftar berubah setelah API menjawab; checkbox barang itu nonaktif selama menunggu). Setelah `clearDone`, barang yang sudah dibeli dibuang dari daftar yang dimuat dan `nextCursor` dipertahankan, karena cursor berbasis posisi sehingga halaman berikutnya dari API sudah tanpa barang itu.
5. **Kegagalan aksi di daftar sebagai SnackBar** lewat `ShoppingListLoaded.actionFailure` (dikosongkan setiap aksi baru), karena daftar tetap valid.
6. **Field jumlah**: hanya angka, paling banyak 3 digit (`digitsOnly` + `LengthLimitingTextInputFormatter(3)`); batas 1–999 ditegakkan API dan error-nya tampil di field. Tidak lebih ketat dari API. Jumlah kosong = tidak dikirim. Barang baru diisi 1.
7. **`FailureView` dan `LoadMoreFooter` disalin dari notes** ke `features/shopping/presentation/widgets/`, bukan diimpor dari notes atau dipindah ke `core`, karena notes dihapus di T-005 dan memindahkannya berarti menyentuh fitur notes.

Usulan untuk `docs/conventions.md` (dikerjakan bersama T-005 saat rujukan notes diganti): pola filter di daftar berpagination (keputusan 3), kegagalan aksi di daftar lewat SnackBar (5), dan pesan kegagalan khusus fitur di field (2).
