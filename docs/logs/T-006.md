# T-006 Login web tetap memakai Auth Emulator setelah `flutter run` diulang

## Status

Selesai. Semua kriteria otomatis terpenuhi dan verifikasi manual dikonfirmasi user di Chrome. Branch: `fix/t-006-web-auth-emulator`.

## Ringkasan

- Bug ditemukan saat verifikasi manual T-005 (lihat bagian Kendala `docs/logs/T-005.md`): login dan register di web gagal dengan "Terjadi kesalahan. Silakan coba lagi." setelah `flutter run` diulang dalam keadaan masih login.
- Spike: bug direproduksi otomatis, dua opsi perbaikan diuji. User memilih opsi a: Flutter web selalu dijalankan dengan `--web-browser-flag=--incognito`. Tidak ada perubahan kode.
- Flag ditambahkan ke semua perintah Flutter web di `README.md`, `apps/app/README.md`, dan `docs/conventions.md` (bagian Config dan "Lingkungan Flutter dan Android"), beserta penjelasan singkat penyebabnya.
- Entri T-006 dan T-007 ditambahkan ke `docs/TASKS.md` (disetujui user).

## Hasil spike

### Cara menguji

`flutter run -d chrome` sungguhan, disambungkan lewat Chrome DevTools Protocol oleh skrip Node di luar repo: membaca `window.firebase_auth.getAuth().emulatorConfig` (yang diekspos plugin), isi IndexedDB `firebaseLocalStorageDb`, dan request `identitytoolkit`/`securetoken` di Network. Chrome ditutup lewat `Browser.close` (sama dengan menutup jendela), sehingga `flutter run` menyalin profil kembali ke `apps/app/.dart_tool/chrome-device`.

### Penyebab (terbukti)

1. `flutter run -d chrome` menjalankan Chrome dengan profil sementara yang disalin dari `apps/app/.dart_tool/chrome-device` dan disalin kembali (seluruh folder `Default`, termasuk IndexedDB) saat Chrome ditutup (`flutter_tools/lib/src/web/chrome.dart`, `_cacheUserSessionInformation`).
2. `firebase_auth_web` 6.3.0 membuat instance Auth di dalam `Firebase.initializeApp()` dengan persistence IndexedDB. Bila ada sesi tersimpan, SDK JS langsung memvalidasinya (`POST https://identitytoolkit.googleapis.com/v1/accounts:lookup`), sebelum `main.dart` memanggil `useAuthEmulator()`.
3. Setelah ada request, SDK menolak `connectAuthEmulator` (`auth/emulator-config-failed`); plugin menelan error itu (`firebase_auth_web.dart` baris 566–575).
4. Request auth berikutnya ke Google dengan `demo-api-key` → `400 API key not valid` → kode tidak dikenal → `FailureCode.unknown` → pesan umum.
5. Muat ulang (F5) dalam run yang sama aman: plugin menyimpan alamat emulator di `sessionStorage` (`[DEFAULT]-firebaseEmulatorOrigin`) dan memakainya segera setelah membuat instance Auth. `sessionStorage` tidak bertahan saat Chrome ditutup. Ini juga sebabnya bug tidak terlihat di verifikasi T-004, dan template (`docs/template-build/logs/T-014.md`) hanya menguji pemulihan sesi lewat F5.

### Hasil per opsi

| Percobaan | Request validasi saat start | `emulatorConfig` | Hasil |
| --- | --- | --- | --- |
| Tanpa perbaikan, restart `flutter run` dengan sesi tersimpan | `accounts:lookup` ke `identitytoolkit.googleapis.com` | `null` | bug: sesi dihapus, login/register ke Google |
| a. `--web-browser-flag=--incognito` | tidak ada | port 9099 | berhasil; sesi lama di profil diabaikan; setiap run mulai belum login |
| b. Isi kunci `sessionStorage` plugin sebelum `Firebase.initializeApp()` (kode di `main.dart`, conditional import `dart:js_interop`) | `accounts:lookup` ke `localhost:9099` | port 9099 | berhasil; tetap login antar-run; akun yang hilang dari emulator → sesi dibersihkan, register berhasil |
| c. Matikan persistence web | tidak diuji | — | sesi yang sudah tersimpan tetap divalidasi ke Google di run pertama setelah perbaikan, karena validasi terjadi sebelum kode kita berjalan |

### Keputusan

User memilih opsi a (tanpa perubahan kode). Opsi b ditolak karena bergantung pada nama kunci internal `firebase_auth_web`. Kode percobaan opsi b dibuang dan tidak pernah di-commit.

Verifikasi otomatis opsi a dengan perintah baru (lewat harness CDP), dimulai dari profil `chrome-device` yang menyimpan sesi login dari run tanpa flag:

1. Run dengan flag: `emulatorConfig` port 9099, tidak ada request ke Google, belum login.
2. Register → berhasil; F5 → tetap login; logout → login lagi → berhasil.
3. Chrome ditutup dalam keadaan login, `flutter run` dengan flag lagi: `emulatorConfig` port 9099, belum login; register berhasil.

### Langkah verifikasi manual

Persiapan: `docker compose up -d --wait`, `pnpm --filter api dev`.

1. Di `apps/app`: `flutter run -d chrome --web-port 8081 --web-browser-flag=--incognito --dart-define-from-file=config/dev.json`.
2. Daftar akun baru (atau masuk) → halaman **Daftar belanja**.
3. Dalam keadaan masih login, hentikan aplikasi (Ctrl+C di terminal atau tutup jendela Chrome).
4. Jalankan lagi perintah langkah 1 → halaman **Masuk** tampil (setiap run dimulai belum login; ini perilaku yang diharapkan dengan mode incognito).
5. Masuk dengan akun langkah 2 → berhasil. Keluar (logout) → kembali ke halaman Masuk. Daftar akun baru lainnya → berhasil.

Profil Chrome tidak perlu dihapus di langkah mana pun.

## Keputusan yang diambil sendiri

1. **Langkah verifikasi manual di log T-004 dan T-005 tidak diubah.** Itu catatan sejarah perintah yang benar-benar dijalankan saat itu; langkah manual baru (log ini) memakai flag.
2. **Komentar `main.dart` (`flutter run --dart-define-from-file=config/dev.json`) tidak diubah**, karena berlaku untuk semua platform, bukan perintah khusus web.
3. **Urutan langkah manual disesuaikan**: setelah restart dengan flag user sudah dalam keadaan belum login, jadi "logout" dilakukan setelah login ulang. Semua aksi di kriteria (login, hentikan, jalankan lagi, logout, login, register) tetap tercakup.
4. **Profil `apps/app/.dart_tool/chrome-device` dihapus setelah spike.** Profil itu berisi sesi akun uji yang dibuat spike dan bisa memicu bug bila aplikasi dijalankan tanpa flag. Chrome sudah ditutup; folder ini cache Flutter yang di-ignore Git dan dibuat ulang otomatis.
5. **Akun uji di Auth Emulator.** Spike membuat beberapa akun `spike-…@example.com` dan menghapus satu di antaranya untuk menguji skenario akun hilang. Akun lain tidak disentuh. Data emulator hanya di memori.
