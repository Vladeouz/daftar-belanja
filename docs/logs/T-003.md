## Keputusan yang diambil sendiri

1. **Enum filter domain sendiri (`ShoppingItemStatus`)**, bukan enum kontrak, karena `domain/` tidak boleh mengimpor `api_client`. Nama sama dengan DTO; `data/` memakai prefix `dto.`. Pemetaan ke enum kontrak dilakukan repository (`shoppingItemStatusToDto`, switch tanpa `default`), sehingga data source tetap menerima tipe kontrak seperti pola notes.
2. **`status` `null` = tidak dikirim** (bawaan API `all`), sejalan dengan aturan "parameter opsional `null` berarti tidak dikirim".
3. **Tanpa use case khusus "tandai sudah dibeli"**: menandai memakai `UpdateShoppingItem(id, isDone: ...)`, karena API juga memakai `PATCH` yang sama. Bila presentation (T-004) butuh nama yang lebih jelas, bisa ditambahkan di sana.
4. **`clearDone` mengembalikan `Result<int>`** (jumlah terhapus), bukan entity hasil, karena respons API hanya `{ deletedCount }`.
5. **Nama use case `CreateShoppingItem`** (bukan `AddShoppingItem`), mengikuti nama operasi API dan pola notes.
