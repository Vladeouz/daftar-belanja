### Langkah verifikasi manual untuk user

1. Push branch: `git push -u origin chore/t-018-ci-github-actions`. Buka tab **Actions** di GitHub, workflow **CI** untuk commit itu harus hijau. Run pertama lebih lama karena image emulator di-build tanpa cache (lokal 395 detik di T-002); run berikutnya memakai cache.
2. Buat commit uji yang merusak `contract:check`, misalnya ubah `summary: 'Health check'` menjadi `summary: 'Health check uji CI'` di `apps/api/src/features/system/http/health.route.ts` **tanpa** `pnpm contract:generate`, commit, push.
3. Pastikan workflow merah, langkah `pnpm check` gagal, dan ringkasan menandai `contract:check` GAGAL dengan nama file `packages/contract/openapi.json (isi berbeda)`. Artifact `check-logs` tersedia di halaman run.
4. `git revert HEAD`, push, dan pastikan workflow hijau lagi.
5. Konfirmasi ke agent; setelah itu task dicentang.

Langkah 1 sudah dilakukan user pada 2026-10-04. Langkah 2–4 dilakukan user pada 2026-10-10 (commit `d6cae2b` dan revert `0b07695`), lalu agent memeriksa hasilnya lewat `gh`.

## Keputusan yang diambil sendiri

- **CI menjalankan `pnpm check`**, bukan menyalin ketujuh langkahnya satu per satu, agar daftar langkah hanya ada di satu tempat (`STEPS` di `scripts/check.mjs`). Konsekuensi: semua langkah tampil dalam satu step log GitHub; ringkasan di akhir menunjukkan langkah yang gagal, dan output lengkapnya ada di artifact `check-logs`.
- **PostgreSQL sebagai `services`, emulator lewat `docker compose`.** Service GitHub Actions hanya bisa memakai image yang sudah ada di registry; image emulator di-build dari repo, jadi dijalankan lewat Compose dengan `--no-build` setelah di-build dengan cache GHA. Tidak ada image yang dipublikasikan ke registry.
- **Trigger `push` semua branch dan `pull_request`**, sesuai FR-14 harfiah. Untuk PR dari branch di repo yang sama, workflow berjalan dua kali (push dan pull_request). Bila tidak diinginkan, bisa diganti `push: branches: [master]` + `pull_request`.
- **Versi action dipin ke major tag terbaru** (dicek dengan `git ls-remote` pada 2026-10-04): `actions/checkout@v7`, `actions/setup-node@v7`, `pnpm/action-setup@v6`, `subosito/flutter-action@v2`, `actions/upload-artifact@v7`, `docker/setup-buildx-action@v4`, `docker/build-push-action@v7`.
- **README tidak diubah** (di luar daftar `files`). Usulan untuk T-020: tambahkan satu baris tentang CI ke README.

Usulan untuk `docs/conventions.md` (bagian "Script dan perintah root"): CI hanya menjalankan `pnpm check`; langkah verifikasi baru ditambahkan ke `scripts/check.mjs`, bukan ke `ci.yml`. Versi Flutter di `ci.yml` diperbarui bersamaan dengan README dan tabel versi.

Percobaan ulang langsung hijau (Unit test API 5 dtk). Tidak diperbaiki di task ini (file di luar daftar `files`). Usulan perbaikan sebagai task `fix` terpisah: beri test itu timeout eksplisit (misalnya `it(..., 30_000)`), lebih besar dari `timeout: 20_000` milik `spawnSync`.
- GitHub memberi anotasi bahwa `ubuntu-latest` akan pindah ke Ubuntu 26 mulai 19 Oktober 2026. Bila CI gagal setelah tanggal itu, periksa ini lebih dulu. Pilihan lainnya: pin `runs-on: ubuntu-24.04`.
- `actionlint` 1.7.12 tidak mengenal semua input action versi terbaru, jadi pemeriksaannya terbatas pada sintaks dan ekspresi.
