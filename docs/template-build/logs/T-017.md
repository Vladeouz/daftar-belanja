- **Semua langkah selalu dijalankan**, walaupun langkah sebelumnya gagal, sesuai FR-03 ("langkah lain tetap dilaporkan"). Output langkah tidak ditangkap (stdio diteruskan) agar pesan error terlihat utuh; ringkasan di akhir hanya status, waktu, dan exit code.
- **Biome dipanggil lewat `pnpm lint`**, bukan `biome check .` langsung, agar satu sumber perintah.
- **Petunjuk Docker hanya ditambahkan ke ringkasan bila engine Docker memang tidak merespons**, agar tidak menyesatkan saat integration test gagal karena hal lain (seperti kegagalan pg-boss di bawah).
- **Tidak ada opsi untuk melewati langkah** (misalnya tanpa Flutter). Paling sederhana; bisa ditambah bila CI (T-018) butuh.
- **Tidak menambah script root `dev`** yang tercantum di pohon folder PRD: tidak ada di daftar `files` dan belum jelas apakah harus menjalankan API saja atau API dan Flutter. README memakai `pnpm --filter api dev`. Usulan: putuskan di T-020 atau hapus dari pohon folder PRD.
- **Uji gagal dengan `DATABASE_URL` ke port tertutup**, bukan mematikan Docker, agar layanan tidak perlu dimatikan; jalur kode sama (koneksi PostgreSQL ditolak). Petunjuk Docker di ringkasan (cek `docker version`) belum diuji dengan Docker Desktop yang benar-benar mati; bisa diuji user: matikan Docker Desktop, `pnpm check`, baris "Integration test API" harus berketerangan "Docker tidak merespons …".

- `pnpm check` adalah satu perintah verifikasi dan harus hijau sebelum task dicentang; langkah baru (misalnya tool baru) ditambahkan ke `STEPS` di `scripts/check.mjs`.
- Integration test yang memeriksa keadaan server PostgreSQL (misalnya `pg_stat_activity`) membatasi ke `current_database()`, karena API dev bisa berjalan bersamaan di database utama.

## Catatan: deteksi flaky test dan log kegagalan

Permintaan user setelah task dicentang: jalankan `pnpm check` minimal 5 kali berturut-turut (sekali setelah cache tsx dihapus), simpan output lengkap langkah yang gagal ke file, dan perbaiki penyebab test yang gagal acak tanpa menambah retry. Dikerjakan di branch yang sama.

- **`scripts/check.mjs`**: output setiap langkah dialirkan lewat pipe, tampil di terminal sekaligus ditampung. Bila langkah gagal, output lengkapnya ditulis ke `.check-logs/<waktu run UTC>/<no>-<langkah>.log` dengan header (perintah, folder, waktu mulai, durasi, exit code). Jalur file tampil di kolom Keterangan ringkasan. stderr digabung ke stdout lewat `2>&1` (berlaku di cmd.exe dan sh) agar urutan baris di log sama dengan di terminal; percobaan pertama memakai dua pipe terpisah dan baris Biome tercampur di tengah baris.
- **Konsekuensi:** karena output tidak lagi langsung ke terminal, tool tidak menampilkan warna, dan `flutter test` memakai format satu baris per test (format non-TTY).
- **`.gitignore`**: `.check-logs/`. **`README.md`**: penjelasan lokasi log.
