- `src/app.ts`: `createApp({ logger, corsOrigins })`.

## Keputusan yang diambil sendiri

- **Hanya env yang dipakai kode T-005** (`NODE_ENV`, `PORT`, `LOG_LEVEL`, `CORS_ORIGINS`). `DATABASE_URL` dan `FIREBASE_*` ditambahkan di T-006 dan T-007.
- **`CORS_ORIGINS` wajib tanpa default**, agar produksi tidak pernah membuka origin secara tidak sengaja. Konsekuensi: `.env` lokal perlu baris `CORS_ORIGINS=http://localhost:8081` (lihat Kendala).
- **"Origin ditolak" = tanpa header `Access-Control-Allow-Origin`** (perilaku standar `hono/cors`; preflight tetap 204 dan browser yang memblokir). Tidak membalas 403, karena request tanpa `Origin` (curl, aplikasi mobile) tetap harus bisa lewat.
- **Deteksi `required` lewat data mentah**, bukan `issue.input` seperti di spike T-003. Zod 4 tidak menyertakan `input` di issue secara default (dicek: `{ n: 'x' }` pada `z.number()` tidak punya `input`), sehingga cara spike akan memberi `required` juga untuk field bertipe salah. `@hono/zod-validator` mengirim data mentah di `result.data`, tetapi tipe `Hook` `@hono/zod-openapi` 1.6.3 tidak mendeklarasikannya, jadi dibaca lewat cast; test `required` dan `invalid_type` menjaganya saat upgrade. Field yang dikirim `null` tetap `invalid_type`. `_root` tidak pernah `required`.
- **`AppError(code, message)` tanpa `details`, status diturunkan dari `code`**, karena PRD membatasi `details` untuk `VALIDATION_ERROR`. `ValidationError` adalah subclass yang membawa `details`.
- **`HTTPException` 4xx dipetakan menurut status; status di luar daftar (405, 413, …) menjadi `BAD_REQUEST` dengan status aslinya; 5xx menjadi `INTERNAL_ERROR`** dan dicatat di log. Daftar `ErrorCode` tetap 7 kode PRD.
- **Redaksi sampai kedalaman 4 lewat path eksplisit** (wildcard pino satu level), mengikuti gym-membership; `authorization` dan `Authorization` keduanya terdaftar.
- **Header `X-Request-Id`** (`hono/request-id`) dan diekspos lewat CORS (`exposeHeaders`), agar Flutter web bisa membacanya untuk laporan error.
- **Test env lewat proses nyata** (`test/unit/server.test.ts` men-spawn `node --import tsx src/server.ts`, ~0,6 detik), agar kriteria "proses berhenti" dibuktikan, bukan hanya `loadEnv()`.
- **`context.ts` (hanya tipe) diuji lewat `context.test.ts`** yang membaca `c.var.requestId` dan `c.var.log`, agar setiap file `src/core` punya test (NFR-05).
- **TypeScript `target`/`lib` ES2024** (sama dengan spike), plus `noUncheckedIndexedAccess`, `verbatimModuleSyntax`, `isolatedModules` dari gym-membership.
- **Script `dev`/`start` memakai `--env-file-if-exists=../../.env`**, sehingga CI (tanpa `.env`) bisa memberi env lewat shell.

Usulan untuk `docs/conventions.md`: sudah ditambahkan (bagian API, Env, Logger, Format error, Test API).

## Perbaikan: timeout test `server.test.ts` (T-005)

### Ringkasan

- `apps/api/test/unit/server.test.ts` menjalankan `node --import tsx src/server.ts` lewat `spawnSync`. Start dingin di Windows saat mesin sibuk butuh 5,1–6,7 dtk, sedangkan test memakai batas default Vitest 5 dtk, jadi kadang gagal dengan `Test timed out in 5000ms`.
