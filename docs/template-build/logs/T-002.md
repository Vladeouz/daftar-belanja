## Keputusan yang diambil sendiri

- **Dua container dari satu image** untuk Auth dan Storage (bukan satu container dengan dua emulator), agar sesuai "tiga layanan healthy" dan masing-masing punya healthcheck sendiri. YAML anchor `x-firebase-emulator` mencegah duplikasi.
- **`firebase.json` dan `storage.rules` di-mount, bukan di-`COPY`**. Konteks build hanya `docker/firebase-emulator/` (tidak perlu `.dockerignore`), dan mengubah aturan cukup dengan `--force-recreate`, tanpa build ulang.
- **Base `node:24-trixie-slim` + OpenJDK 21**: sama dengan Node proyek (D-10); `firebase-tools` versi baru butuh Java 21+, dan Debian bookworm hanya punya OpenJDK 17.
- **Healthcheck Storage** memakai list objek dengan token admin emulator (`Bearer owner`), karena root emulator menjawab `501`. `curl -s` tanpa `-f` akan dianggap healthy sebelum emulator siap.
- **Default di compose** (`${POSTGRES_DB:-template}`, dan seterusnya) sama dengan `.env.example`, agar compose tetap jalan tanpa `.env` (misalnya di CI) dan dengan `.env` kosong. Kredensial `template/template` hanya untuk lokal.
- **`.env.example` hanya berisi variabel yang sudah dipakai** (compose). `DATABASE_URL`, `FIREBASE_AUTH_EMULATOR_HOST`, dan seterusnya ditambahkan oleh task yang pertama kali membacanya (T-005/T-006).
- **Cek layanan di `prereq` bersifat opsional** (PERINGATAN): prereq memeriksa lingkungan, dan layanan memang belum jalan sebelum `docker compose up`. Status dibaca dari `docker compose ps`, sama dengan yang ditunggu `--wait`.
- **`run()` di `prereq.mjs` kini memakai `cwd: root`**, agar `docker compose` menemukan `docker-compose.yml` walaupun script dipanggil dari subfolder.
- **Nama image** `profil-a/firebase-emulator:local`.

Usulan untuk `docs/conventions.md` (bagian baru "Layanan lokal", diisi lengkap di T-020): nama service compose, port, project `demo-template`, dan cara memuat ulang aturan Storage.
