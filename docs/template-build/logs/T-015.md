## Ringkasan

- `features/notes/domain`: entity `Note` dan `NotePage` (`items`, `nextCursor`, `hasMore`), interface `NoteRepository` (`list`, `get`, `create`, `update`, `delete`), use case `ListNotes`, `GetNote`, `CreateNote` (judul di-`trim`), `UpdateNote` (judul di-`trim` bila diisi), `DeleteNote`.
- `features/notes/data`: `NoteRemoteDataSource` (membungkus `NotesClient` hasil generate, mengembalikan DTO, melempar `DioException`), `note_mapper.dart` (`noteFromDto`, `notePageFromDto`), `ApiNoteRepository` (lewat `apiCall`/`apiCallRaw`, sehingga `NOT_FOUND` dan `VALIDATION_ERROR` + `details` menjadi `Failure`).
- `features/notes/notes_dependencies.dart`: `registerNotesDependencies(GetIt)` (data source, repository, use case), dipanggil dari `configureDependencies`. Cubit ditambahkan di T-016.
- **Perbaikan kontrak:** client Dart hasil generate mengirim `null` untuk field opsional yang tidak diisi (`{"title": null, "body": "x"}`), padahal API menolak `null` pada field `optional()` (`422 invalid_type`). Akibatnya `PATCH` dengan satu field dan `POST` tanpa `body` selalu gagal. Diperbaiki dengan `include_if_null: true` di `packages/contract/dart/swagger_parser.yaml`, lalu `pnpm contract:generate`. Field opsional kini diberi `@JsonKey(includeIfNull: false)`; field wajib yang nullable (`nextCursor`, `User.email`, `User.displayName`) tetap ditulis sebagai `null`. `openapi.json` tidak berubah.
- `docs/conventions.md`: bagian "Fitur berbasis API (contoh: notes)", pola test fitur berbasis API, catatan `include_if_null` di bagian kontrak.

## Keputusan yang diambil sendiri

- **Kontrak diperbaiki di konfigurasi generator** (`include_if_null: true`), bukan dengan mengakali di data source atau melonggarkan API agar menerima `null`. Alasan: hasil generate tetap satu sumber kebenaran, API dan `openapi.json` tidak berubah, dan berlaku untuk semua fitur berikutnya. Tidak mengubah keputusan di bagian 8 PRD (D-01/D-02 tetap).
- **Data source sebagai kelas tersendiri** (`NoteRemoteDataSource`) di atas `NotesClient`, sesuai PRD bagian 3 ("data source memakai `api_client`") dan kriteria "data source di-mock". Data source tidak menangkap exception; `Result` dibentuk di repository.
- **Nama implementasi `ApiNoteRepository`** (mengikuti pola `FirebaseAuthRepository`: sumber data + entity + `Repository`).
- **Import `api_client` dengan prefix `dto`** di `data/` karena nama kelas DTO sama dengan entity (`Note`, `NotePage`).
- **Entity halaman `NotePage` sendiri** (bukan generic `Page<T>`): hanya satu fitur yang butuh; generic bisa dibuat di proyek bila fitur kedua muncul.
- **`limit` opsional di repository dan use case** (`null` = bawaan API 20), agar presentation bisa memilih ukuran halaman tanpa menduplikasi angka bawaan.
- **Use case tidak memvalidasi** (judul kosong, minimal satu field): hanya `trim` judul, sesuai "Aturan bisnis: API vs client". Validasi lokal bila perlu ditambahkan di presentation (T-016).
- **Test data source memakai `NotesClient` asli + `FakeHttpAdapter`** (bukan mock), sehingga body request yang benar-benar dikirim ikut teruji; test inilah yang menangkap masalah `null`.
- **DI untuk domain dan data didaftarkan sekarang**, Cubit menyusul di T-016.

Usulan untuk `docs/conventions.md`: sudah ditambahkan (bagian "Fitur berbasis API (contoh: notes)", pola test, `include_if_null`).
