## Keputusan yang diambil sendiri

- **Presisi cursor: `to_char(... 'US')` dari database, kolom tetap mikrodetik.** Alternatifnya kolom `timestamp(3)`, tetapi itu menyimpang dari helper `createdAt()` bersama dan harus diingat untuk setiap tabel baru. Dengan cara ini hanya query daftar yang berbeda; respons API tetap milidetik.
- **Index dengan `.desc().nullsFirst()`.** Ditemukan lewat `EXPLAIN`: `.desc()` Drizzle menulis `DESC NULLS LAST`, sehingga PostgreSQL memakai index hanya untuk filter lalu tetap `Sort`. Migrasi 0001 dibuat ulang sebelum di-commit (belum pernah di-commit, jadi tidak melanggar "migrasi yang sudah di-commit tidak diedit").
- **FK dengan `foreignKey({ name })`**, bukan `.references()`, agar namanya `notes_user_id_fk` mengikuti pola `<tabel>_<kolom>_<jenis>` (nama bawaan Drizzle: `notes_user_id_users_id_fk`).
- **Satu use case per file** dan route menerima use case lewat parameter `registerNoteRoutes(app, deps)`, mengikuti pola `syncUser`.
- **Domain dan use case mengimpor tipe `Page`/`CursorPosition` dari `core/http/pagination.ts`** (hanya `import type`, hilang saat runtime) agar repository bisa mengembalikan halaman dengan `nextCursor` yang sudah dibentuk `buildPage`. Use case juga mengimpor `AppError`, sesuai konvensi format error.
- **Validasi panjang hanya di skema Zod route + CHECK database**, tidak diulang di use case. Batas Zod (UTF-16 code unit) sama atau lebih ketat dari `char_length`, jadi input yang lolos Zod tidak memicu `500`.
- **`title` tidak di-trim**; `' '` adalah judul valid. PRD hanya meminta judul kosong ditolak.
- **Respons `POST` `201` tanpa header `Location`**; PRD tidak memintanya.
- **Unit test route hanya memeriksa DTO dan OpenAPI**; perilaku yang butuh login diuji di integration test, karena `createTestApp()` tanpa database tidak bisa melewati `authenticate`.

Usulan untuk `docs/conventions.md`: sudah ditambahkan (lihat Ringkasan).

## Perbaikan: semua timestamp presisi milidetik (T-008/T-011)

Branch: `fix/timestamp-precision`, dibuat dari `feat/t-011-notes-api` (bukan `master`) karena `feat/t-011-notes-api` belum di-merge dan perbaikan ini mengubah kodenya. Diminta user setelah meninjau T-011. Menggantikan keputusan "Presisi cursor: `to_char(... 'US')` dari database, kolom tetap mikrodetik" di atas.

### Ringkasan

- `apps/api/src/db/schema/columns.ts`: helper `timestamptz()` memakai `precision: 3`, sehingga `createdAt()`, `updatedAt()`, dan `users.last_seen_at` semuanya `timestamptz(3)`.
- Migrasi `apps/api/drizzle/0002_timestamp_precision.sql` (hasil `db:generate --name timestamp_precision`): `ALTER COLUMN ... SET DATA TYPE timestamp (3) with time zone` untuk `users.{last_seen_at,created_at,updated_at}` dan `notes.{created_at,updated_at}`. Nilai lama dibulatkan PostgreSQL ke milidetik; index `notes_user_id_created_at_id_index` dibangun ulang otomatis.
- `drizzle-note-repository.ts`: `to_char` dihapus; `listByUser` memakai `select()` biasa dan `buildPage(rows.map(toNote), limit, (note) => note)`, cursor dari `Date`.
- `core/http/pagination.ts`: hanya komentar `CursorPosition` diperbarui; decoder tetap menerima 0–6 digit pecahan (tidak ada perubahan perilaku helper T-008).
- `docs/conventions.md`: aturan "Semua timestamp presisi milidetik" di bagian Database; bullet "Presisi timestamp" di bagian Pagination ditulis ulang.

### Keputusan yang diambil sendiri

- **Test "mikrodetik" diganti, bukan dipertahankan.** Dengan presisi 3, urutan lama `u300, u200, u100` tidak lagi benar (ketiganya menjadi milidetik yang sama). Test baru membuktikan hal yang relevan sekarang: nilai sub-milidetik dibulatkan ke milidetik yang sama, urutan jatuh ke `id DESC`, dan tidak ada duplikat.
- **Test presisi membaca semua kolom timestamp di `public`**, bukan daftar tetap, agar tabel baru yang lupa memakai helper langsung ketahuan.
- **Test `updated_at` di `schema.int.test.ts` (dari T-006) diubah:** nilai awal `updated_at` diisi 60 detik di masa lalu. Dengan presisi milidetik, insert dan update bisa jatuh di milidetik yang sama sehingga `toBeGreaterThan` bisa gagal acak.
- **Decoder cursor (`pagination.ts`) tidak dipersempit ke 3 digit**: helper T-008 tetap umum, dan cursor lama yang berisi mikrodetik tetap valid (dibandingkan dengan `::timestamptz`).
