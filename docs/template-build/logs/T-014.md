### Langkah verifikasi manual

1. Nyalakan Docker Desktop, lalu di root: `docker compose up -d --wait`. Pastikan Auth Emulator hidup: buka `http://localhost:4000/auth` (Emulator UI) atau `curl http://localhost:9099/`.
2. **Chrome** (di `apps/app`): `flutter run -d chrome --web-port 8081 --dart-define-from-file=config/dev.json`.
   1. App terbuka di halaman **Masuk** (belum login). Ketik `http://localhost:8081/#/notes` atau `/notes` di address bar → tetap diarahkan ke **Masuk**.
   2. Tekan **Belum punya akun? Daftar**, isi email `uji@example.com` dan password `rahasia1`, tekan **Daftar** → masuk ke halaman **Catatan**. User muncul di Emulator UI.
   3. Tekan ikon **Keluar** (kanan atas) → kembali ke **Masuk**.
   4. Login dengan `uji@example.com` dan password `salah123` → tampil **"Email atau password salah."** dalam Bahasa Indonesia, tetap di halaman Masuk.
   5. Login dengan password `rahasia1` → masuk ke **Catatan**. Muat ulang tab (F5) → tetap di **Catatan** (sesi dipulihkan).
   6. Opsional: daftar lagi dengan email yang sama → **"Email sudah terdaftar. Silakan masuk."**; password `123` → **"Password terlalu lemah…"**.
3. **Android emulator**: nyalakan emulator, lalu `flutter run -d emulator-5554 --dart-define-from-file=config/dev.json` (lihat id dengan `flutter devices`). Ulangi langkah 2.2–2.5 (tanpa langkah address bar; F5 diganti tutup-buka app). Host `localhost` otomatis menjadi `10.0.2.2`.
4. Cek ID emulator dengan `flutter devices` (kolom kedua, misalnya `emulator-5554`) atau `adb devices`.

> **Koreksi (ditambahkan setelah T-021):** langkah 1 dan 2.2 di atas merujuk Emulator UI di port 4000 (`http://localhost:4000/auth`). Emulator UI dimatikan sejak T-002 (`firebase.json`: `"ui": { "enabled": false }`), jadi alamat itu tidak bisa dibuka. Pakai `curl http://localhost:9099/` untuk memastikan Auth Emulator hidup, dan untuk melihat user yang terdaftar: `curl -X POST -H "Authorization: Bearer owner" -H "Content-Type: application/json" -d "{}" http://localhost:9099/identitytoolkit.googleapis.com/v1/projects/demo-template/accounts:query`. Teks langkah asli dibiarkan sebagai catatan sejarah.

## Keputusan yang diambil sendiri

- **Kode Firebase Auth masuk ke `FailureCode` (core)**, bukan enum terpisah di fitur. Alasan: `Err` membawa `Failure` dengan `FailureCode`, dan D-03/konvensi menaruh semua teks kegagalan di `failure_messages.dart`. Kode yang ditambah: `invalidCredentials`, `emailAlreadyInUse`, `weakPassword`, `invalidEmail`, `tooManyRequests`. `user-disabled` → `forbidden`, `network-request-failed` → `network`.
- **`invalid-credential`, `wrong-password`, `user-not-found`, `INVALID_LOGIN_CREDENTIALS` → satu `invalidCredentials`** ("Email atau password salah."), agar tidak membocorkan apakah akun ada dan tetap benar baik email enumeration protection aktif atau tidak.
- **SDK Firebase sebagai data source** di `FirebaseAuthRepository`, tanpa kelas data source terpisah: tidak ada DTO, lapisan tambahan hanya akan meneruskan panggilan. Fitur notes (T-015) tetap memakai data source + `api_client`.
- **Sesi app di `AuthSessionCubit` singleton** yang dibaca router (`refreshListenable` + `redirect`), bukan `FirebaseAuth` langsung, agar router bisa diuji dengan repository palsu.
- **`main.dart` menunggu `authStateChanges().first`** alih-alih state "memuat"/splash: lebih sederhana, dan di web sesi tersimpan pulih sebelum router pertama kali me-redirect.
- **Rute terlindungi secara default**: hanya `AppRoutes.public` (`/login`, `/register`) yang terbuka; rute baru otomatis butuh login. Rute tak dikenal saat belum login → login.
- **Rute terlindungi dalam `ShellRoute`** yang memasang `AuthSessionCubit` lewat `BlocProvider.value`, sehingga `SignOutButton` di halaman mana pun (termasuk halaman notes T-016) tidak butuh `getIt`.
- **`createRouter({container})`** mengambil Cubit dari `GetIt` yang diberikan (default `getIt`), agar test router memakai wiring asli dengan repository palsu.
- **Login dan daftar dua halaman/Cubit terpisah** dengan `AuthForm` dan `AuthFormState` bersama. Daftar tanpa konfirmasi password dan tanpa nama tampilan (tidak diminta FR-12). Validasi lokal hanya "wajib diisi"; format email dan panjang password dari Firebase.
- **Setelah daftar user langsung login** (perilaku bawaan Firebase), lalu diarahkan ke notes.
- **Halaman notes sementara di `app_router.dart`** (`_NotesPlaceholderPage`), diganti di T-016; halaman pengganti harus tetap memasang `SignOutButton`.
- **`_StreamListenable` tidak di-dispose**: langganan berakhir saat `AuthSessionCubit` ditutup (stream selesai); Cubit sesi hidup selama app.
- **Mock per fitur di `test/features/auth/mocks.dart`** dan **`FakeAuthRepository`** (akun dalam memori) di `test/features/auth/fake_auth_repository.dart`.
- Dart 3.13 mendukung parameter bernama privat (`required this._signOut`, dipanggil `signOut:`), dipakai karena lint `prefer_initializing_formals`.

Usulan untuk `docs/conventions.md`: sudah ditambahkan (struktur folder fitur, registrasi DI, "Autentikasi Flutter", pola test).
