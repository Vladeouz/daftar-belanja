## Keputusan yang diambil sendiri

- **`firebase-admin` 14.5.0** (tag `latest`, rilis 2026-09-23, lolos `minimumReleaseAge`).
- **Build script `@firebase/util` dan `protobufjs` ditolak (`false`)**, bukan diizinkan. Postinstall `@firebase/util` hanya menyiapkan default auto-init untuk web SDK, `protobufjs` hanya mengecek versi CLI-nya; keduanya tidak dibutuhkan firebase-admin di Node, dan menjalankan script install yang tidak perlu menambah risiko supply chain. Terbukti: semua test lulus tanpa script itu.
- **firebase-admin hanya dengan `projectId`**, tanpa service account: `verifyIdToken` cukup dengan project ID di emulator maupun produksi. Service account baru dibutuhkan untuk FCM/Storage (T-010).
- **`FIREBASE_AUTH_EMULATOR_HOST` divalidasi di `env.ts` dan ditolak di produksi**, karena dalam mode emulator firebase-admin menerima token tanpa tanda tangan.
- **Port `TokenVerifier` mengembalikan `null` untuk token salah**, sedangkan `auth/internal-error` dilempar ulang menjadi `500`, agar gangguan verifikasi tidak tampak sebagai "token salah" bagi client.
- **Upsert di setiap request terautentikasi** (bukan hanya request pertama), karena FR-06 meminta email dan `last_seen_at` diperbarui pada request berikutnya. Konsekuensi: satu `INSERT … ON CONFLICT` per request. Token adalah sumber kebenaran email dan `display_name` (diambil dari klaim `name`).
- **`c.var.user` berisi entity `User` lengkap**, sehingga `GET /v1/me` tidak query ulang. `core/http/context.ts` dan `core/auth/authenticate.ts` mengimpor *tipe* `User` dari `features/users/domain`; users adalah fitur inti template (bukan contoh), jadi ketergantungan tipe ini diterima.
- **Use case `syncUser` satu-satunya use case**; `GET /v1/me` hanya memetakan `c.var.user` ke DTO, jadi tidak dibuat use case `getMe` kosong.
- **Test NFR-03 juga memeriksa route di luar `/v1`** terhadap daftar `PUBLIC_ROUTES`, agar route publik baru harus didaftarkan secara sadar.
- **Akun emulator dibuat dengan email acak dan emulator tidak dibersihkan**, agar akun yang dibuat user secara manual (T-004, T-014) tidak terhapus oleh test.

Usulan untuk `docs/conventions.md`: sudah ditambahkan (bagian Autentikasi, env Firebase, `allowBuilds` bernilai `false`, composition root di `app.ts`, helper token emulator).

## Kendala

- Auth Emulator tidak menerbitkan ID token baru saat `accounts:update` hanya mengubah `displayName` (berbeda dengan perubahan email). Helper `emulator-token.ts` login ulang lewat `accounts:signInWithPassword` bila respons tidak berisi `idToken`.
- **`.env` lokal perlu dua variabel baru** (agent tidak mengubah `.env`). Tambahkan atau salin ulang dari `.env.example`:
  ```
  FIREBASE_PROJECT_ID=demo-template
  FIREBASE_AUTH_EMULATOR_HOST=localhost:9099
  ```
  Tanpa `FIREBASE_PROJECT_ID`, `pnpm --filter api dev` berhenti dengan pesan yang menyebut variabel itu. Test tidak terpengaruh karena memakai default di `test/setup/env.ts`.
