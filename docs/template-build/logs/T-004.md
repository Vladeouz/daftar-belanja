# T-004 Spike Flutter + Firebase Auth Emulator dengan FirebaseOptions dummy

## Status

Selesai. Branch: `chore/t-004-spike-firebase-flutter`.

## Ringkasan

Spike di `spikes/firebase_flutter/` (sementara, dihapus di T-020), dibuat dengan `flutter create --empty --platforms=web,android`:

- `config/dev.json`: FirebaseOptions dummy (`FIREBASE_PROJECT_ID=demo-template`, `FIREBASE_API_KEY=demo-api-key`, `FIREBASE_APP_ID`, `FIREBASE_MESSAGING_SENDER_ID`) serta `USE_EMULATOR`, `AUTH_EMULATOR_HOST`, `AUTH_EMULATOR_PORT`. Dibaca lewat `--dart-define-from-file=config/dev.json` (`String.fromEnvironment`).
- `lib/main.dart`: `Firebase.initializeApp(options: …)` dengan opsi dari config, lalu `FirebaseAuth.instance.useAuthEmulator(host, port)`. Di Android, `localhost`/`127.0.0.1` diganti `10.0.2.2` (`SpikeConfig.resolveHost`). Satu halaman dengan field email/password, tombol **Daftar** (`createUserWithEmailAndPassword`) dan **Login** (`signInWithEmailAndPassword`), status hasil, dan user aktif dari `authStateChanges()`.
- `test/resolve_host_test.dart`: 2 test penggantian host.
- `android/app/src/debug/AndroidManifest.xml`: `android:usesCleartextTraffic="true"` hanya untuk build debug, karena emulator Auth memakai HTTP.
- `android/gradle.properties`: `kotlin.incremental=false` (lihat Kendala).
- Versi dipin: `firebase_core` 4.15.0, `firebase_auth` 6.7.0, `flutter_lints` 6.0.0.

Flutter yang dipakai: **3.47.5 stable** (Dart 3.13.4, framework 6a19cca564). Dicatat di README dan `docs/conventions.md`.

## Keputusan yang diambil sendiri

- **Nama package `spike_firebase_flutter`**, org `com.example`; hanya platform web dan Android (iOS tidak diverifikasi di task ini).
- **Satu `FIREBASE_APP_ID` untuk semua platform** (format Android `1:000000000000:android:…`). Web dan Android menerimanya; emulator tidak memvalidasi app ID atau API key. Di T-013 bisa tetap satu nilai.
- **Nama kunci config** `FIREBASE_*`, `USE_EMULATOR`, `AUTH_EMULATOR_HOST`, `AUTH_EMULATOR_PORT`, dengan host `localhost` yang diganti di Android oleh kode, bukan config terpisah per platform. Diusulkan dipakai di `apps/app/config/dev.json` (T-013).
- **Cleartext hanya di manifest debug**, bukan `network_security_config`, karena paling sederhana dan tidak memengaruhi build rilis.
- **`kotlin.incremental=false`** hanya di `android/gradle.properties` spike, agar spike bisa di-build di mesin ini. Atas arahan user, pengaturan ini **tidak** dibawa ke `apps/app`; masalah beda drive diatasi di mesin lewat `PUB_CACHE`, dan `pnpm prereq` memperingatkannya.
- **Versi NDK dan `compileSdk` di `prereq` dibaca dari `FlutterExtension.kt`** di Flutter SDK (`flutterRoot` dari `flutter --version --machine`), agar ikut berubah saat Flutter di-upgrade; nilai Flutter 3.47.5 menjadi cadangan. Platform 34 untuk plugin Firebase disimpan sebagai konstanta (`FIREBASE_PLUGIN_COMPILE_SDK`), karena plugin belum tentu sudah diunduh saat `prereq` jalan.
- **Paket dianggap terpasang hanya bila isinya lengkap** (`ndk/<versi>/source.properties`, `platforms/android-<level>/android.jar`), karena unduhan Gradle yang macet meninggalkan folder berisi `.installer` saja.
- **File web bawaan `flutter create` dirapikan untuk Biome**: `lang="id"` di `web/index.html` dan `web/manifest.json` diformat. Biome memeriksa HTML dan JSON di seluruh repo, termasuk `apps/app/web/` nanti.
- File IDE (`.idea/`, `*.iml`) hasil `flutter create` dihapus.

Usulan untuk `docs/conventions.md` (bagian Flutter, T-013): kunci config di atas, penggantian `10.0.2.2` di kode, dan cleartext hanya debug. Cek Pub cache serta NDK/SDK Platform sudah dicatat di bagian "Lingkungan Flutter dan Android".

## Hasil spike

**Berhasil. Rekomendasi: tetap memakai D-04** (project `demo-template` dengan FirebaseOptions dummy lewat `--dart-define-from-file`). Tidak perlu `flutterfire configure` atau `google-services.json` untuk development.

Catatan untuk T-013 dan T-014:

1. Di Android muncul peringatan `FirebaseApp failed to initialize because no default options were found` dari `FirebaseInitProvider` native. Peringatan ini wajar; inisialisasi dari Dart dengan opsi eksplisit tetap berjalan.
2. `useAuthEmulator` harus dipanggil setelah `Firebase.initializeApp` dan sebelum operasi Auth apa pun.
3. Build debug Android butuh cleartext ke `10.0.2.2`.
4. Plugin Firebase meminta Android SDK Platform 34 dan 36 serta NDK 28.2.13676358. Atas permintaan user, `pnpm prereq` kini memeriksanya (opsional) beserta drive pub cache.
5. `apps/app` tidak memakai `kotlin.incremental=false`; developer Windows dengan repo di luar drive pub cache mengatur `PUB_CACHE`.

## Kendala

- **Endpoint pemeriksaan akun di TASKS awal salah.** `GET http://localhost:9099/emulator/v1/projects/demo-template/accounts` dijawab `405 Method GET not allowed`; endpoint itu hanya menerima `DELETE` (menghapus semua akun). Atas persetujuan user, kriteria diganti dengan `POST …/identitytoolkit.googleapis.com/v1/projects/demo-template/accounts:query` (header `Authorization: Bearer owner`, body `{}`).
- **NDK 28.2.13676358 tidak terpasang dan Gradle gagal memasangnya** (build pertama gagal setelah 16 menit: `Android sdkmanager did not install NDK`). `sdkmanager` sudah usang dan meneruskan ke Android CLI dengan sintaks lain (`Package ndk not found`). Dipasang dengan `%LOCALAPPDATA%\Android\sdk\cmdline-tools\latest\bin\android.exe sdk install ndk/28.2.13676358`.
- **Gradle macet saat memasang SDK Platform 36** (folder hanya berisi `.installer`). Folder setengah jadi dihapus, lalu dipasang dengan `android sdk install platforms/android-36` (84 detik). SDK Platform 34 berhasil dipasang Gradle sendiri.
- **Kompilasi Kotlin plugin gagal karena beda drive**: `:firebase_core:compileDebugKotlin` → `Could not close incremental caches … this and base files have different roots`. Proyek di `D:` dan pub cache di `C:\Users\…\AppData\Local\Pub\Cache`. Untuk spike diatasi dengan `kotlin.incremental=false` di `android/gradle.properties`. Untuk `apps/app`, user memilih solusi di mesin (`PUB_CACHE` di drive yang sama), yang kini diperingatkan `pnpm prereq`. `PUB_CACHE` di mesin ini belum diubah; itu dilakukan user.
- Di emulator ada akun `uji@example.com` dan `uji2@example.com` dari percobaan user sebelumnya; tidak dihapus.
