## Status

Selesai. Branch: `feat/t-006-database`.

## Ringkasan

Drizzle ORM + `pg` di `apps/api`, dirujuk dari gym-membership lalu disesuaikan dengan PRD bagian 3 dan 4:

- `src/db/schema/columns.ts`: helper `id()`, `timestamptz()`, `createdAt()`, `updatedAt()` (`$onUpdate`).
- `src/db/schema/users.ts`: tabel `users` sesuai bagian 4 PRD (`id`, `firebase_uid` UNIQUE `users_firebase_uid_unique`, `email` nullable dengan CHECK lowercase, `display_name`, `last_seen_at`, `created_at`, `updated_at`).
- `drizzle/0000_init.sql` + `drizzle/meta/` hasil `drizzle-kit generate --name init`.
- `src/db/client.ts`: `createDb(url)` → `{ db, pool, close }`, `runMigrations(db)`, `MIGRATIONS_FOLDER` yang berlaku dari `src/db` maupun `dist/db` (T-019).
- `src/db/migrate.ts`: CLI `db:migrate`; hanya membaca `DATABASE_URL` lewat `loadDatabaseUrl()`.
- `src/core/config/env.ts`: `DATABASE_URL` (URL `postgres://`/`postgresql://`, wajib) dan `loadDatabaseUrl()`.
- Script `test:int`, `db:generate`, `db:migrate` di `apps/api/package.json`.
- `test/setup/db.ts` (global setup): membuat ulang `<nama>_test` dan menjalankan migrasi; pesan error menyebut Docker bila PostgreSQL tidak bisa dihubungi.
- `test/helpers/db.ts`: `useTestDb()` (pool + `TRUNCATE` semua tabel `public` sebelum setiap test) dan `truncateAll()`.
- `test/int/db/schema.int.test.ts`: 9 test (kolom dan tipe, idempotensi migrasi, unique `firebase_uid`, upsert `ON CONFLICT`, CHECK email, `updated_at`, nama database test, TRUNCATE, database utama tidak tersentuh).

## Keputusan yang diambil sendiri

- **Versi stable, bukan Drizzle 1.0 RC.** `drizzle-orm` 0.45.3 dan `drizzle-kit` 0.31.11 adalah tag `latest`; 1.0 masih `rc`.
- **`pg` 8.23.0, bukan 8.23.1.** 8.23.1 rilis 2026-09-30 sehingga `pnpm add` menambahkan `minimumReleaseAgeExclude` untuk empat paket `pg*` ke `pnpm-workspace.yaml`. Saya batalkan perubahan itu dan memakai 8.23.0 agar supply-chain policy tidak dilonggarkan. Dicatat di `conventions.md` sebagai aturan.
- **`DATABASE_URL` wajib di skema env server sekarang**, walau server baru memakainya di T-007, agar validasinya satu tempat. `db:migrate` memakai `loadDatabaseUrl()` (pick dari skema yang sama) supaya tidak butuh `CORS_ORIGINS`. Konsekuensi: `pnpm --filter api dev`/`start` kini juga butuh `DATABASE_URL` di `.env` (lihat Kendala).
- **CHECK `users_email_lowercase_check` (`email = lower(email)`)**, karena PRD menyebut email "lowercase" dan konvensi meminta aturan penting ditegakkan constraint. Normalisasi ke lowercase tetap tugas kode upsert (T-007).
- **Nama constraint eksplisit `<tabel>_<kolom>_<jenis>`**, agar test dan pemetaan error `CONFLICT` nanti bisa merujuknya.
- **Nama database test diturunkan dari `DATABASE_URL`** (`<nama>_test`), sama dengan PRD `<POSTGRES_DB>_test` selama `DATABASE_URL` memakai `POSTGRES_DB`. Global setup mengimpor `test/setup/env.ts` karena berjalan di proses utama Vitest, sehingga default env sama dengan worker.
- **TRUNCATE dinamis atas semua tabel schema `public`** (`restart identity cascade`), bukan daftar tabel manual, agar tabel baru tidak terlupa. Schema `drizzle` (riwayat migrasi) dan `pgboss` tidak ikut.
- **"Database utama tidak tersentuh" dibuktikan dua cara:** test memastikan `current_database()` adalah `<nama>_test` dan baris yang ditulis test tidak ada di database utama; ditambah verifikasi manual dengan baris penanda.
- **Migrasi diberi nama `0000_init`** (`--name init`), sehingga T-011 menjadi `0001_<nama>`.

Usulan untuk `docs/conventions.md`: sudah ditambahkan.
