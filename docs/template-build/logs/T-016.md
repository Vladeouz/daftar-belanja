## Keputusan yang diambil sendiri

- **Dua Cubit** (`NotesListCubit` untuk daftar, `NoteFormCubit` untuk buat/ubah/hapus), satu per halaman, sesuai pola satu Cubit halaman di fitur auth.
- **Hasil form dikembalikan lewat `context.pop(state)`** dan diterapkan ke daftar secara lokal (`noteSaved`, `noteDeleted`), bukan memuat ulang halaman pertama. Alasan: posisi gulir dan halaman yang sudah dimuat tetap; note baru ditaruh paling atas sesuai urutan API (`created_at DESC`).
- **Hapus ada di halaman form** (ikon di `AppBar` + dialog konfirmasi), bukan geser di daftar. Paling sederhana dan satu Cubit menangani semua perubahan.
- **Muat saat digulir lewat baris terakhir `ListView.builder`** (`LoadMoreFooter`) alih-alih `ScrollController`: lebih sedikit kode dan otomatis memuat bila halaman pertama tidak memenuhi layar. Gagal tidak dicoba ulang otomatis (menghindari loop saat API mati).
- **Validasi lokal judul hanya "wajib diisi" + `maxLength: 120`** (penghitung karakter Flutter tidak lebih ketat dari Zod), sesuai "Aturan bisnis: API vs client". Error validasi API tetap ditampilkan per field.
- **Rute form sebagai rute anak `/notes`** dan **`GoRouter.optionURLReflectsImperativeAPIs = true`**: tanpa opsi itu `context.push` tidak mengubah URL di web, sehingga tombol kembali browser dan muat ulang tidak sesuai halaman yang tampil. Opsi ini statis (berlaku global) dan di-set di `createRouter`.
- **`FailureView` ditaruh di `features/notes/presentation/widgets/`**, bukan di `core`, karena baru dipakai satu fitur. Bisa dipindah ke `core` bila fitur kedua butuh.
- **Tanggal dengan `MaterialLocalizations.formatMediumDate`**, tanpa menambah package `intl`.
- **`SignOutButton` juga dipasang di halaman form**, mengikuti konvensi "halaman terlindungi memasang `SignOutButton`".

Usulan untuk `docs/conventions.md`: sudah ditambahkan (Presentation di bagian "Fitur berbasis API", pola test presentation dan test alur).

## Catatan perbaikan: daftar basi setelah form dibuka lewat URL

Branch: `fix/notes-list-stale-after-deep-link` (dari `master`). Memperbaiki kendala kedua di atas.

- **Penyebab:** bila form dibuka lewat URL (`/notes/<id>`, misalnya halaman dimuat ulang di web), daftar di bawahnya tidak memanggil `context.push`, sehingga hasil `context.pop(NoteFormSaved)` tidak diterima siapa pun dan daftar tetap menampilkan data lama.
- **Perbaikan** (`apps/app/lib/features/notes/presentation/pages/notes_page.dart`, `NotesPage` menjadi `StatefulWidget`):
  - `_openForm`: `push` selesai tanpa state (kembali tanpa menyimpan) → `cubit.load()`.
  - Form dibuka lewat URL: `didChangeDependencies` memantau `ModalRoute.isCurrentOf(context)`; saat rute daftar kembali paling atas dan form tidak dibuka lewat `_openForm`, daftar memanggil `cubit.load()`. Flag `_openedHere` mencegah muat ganda.
  - Mencoba perbaikan yang lebih sempit dulu (hanya `cubit.load()` di `_openForm` saat hasil `null`): test URL tetap gagal (`['Catatan 2', 'Catatan 1']`), karena `_openForm` tidak pernah berjalan pada jalur URL. Karena itu jalur kedua diperlukan.
- **Konsekuensi:** kembali dari form tanpa menyimpan kini memuat ulang halaman pertama, jadi halaman berikutnya yang sudah dimuat dan posisi gulir hilang. Simpan dan hapus dari form yang dibuka lewat daftar tetap diterapkan tanpa memuat ulang.
- **Test baru** (`apps/app/test/features/notes/presentation/notes_flow_test.dart`), keduanya gagal sebelum perbaikan:
  - "kembali dari form tanpa hasil → halaman pertama dimuat ulang": data berubah di repository selama form terbuka, lalu kembali → note baru tampil.
  - "dibuka lewat URL › /notes/<id>, simpan, kembali → daftar menampilkan data terbaru": buka `/notes/note-1`, ubah judul, simpan → kembali ke `/notes` dan daftar berisi `['Catatan 2', 'Diubah']`.
