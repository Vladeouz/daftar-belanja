# T-009 pg-boss: lifecycle, graceful shutdown, job `system.heartbeat`

## Status

Selesai. Branch: `feat/t-009-pg-boss`.

## Ringkasan

- `apps/api/src/core/jobs/boss.ts`: `startBoss({ databaseUrl, runWorker, logger, jobs, schema? })`. Bila `runWorker` false, mengembalikan `null` tanpa membuka koneksi. Bila true: membuat `PgBoss` (schema `pgboss`, listener `error` ke log), `start()`, lalu untuk setiap `JobDefinition` menjalankan `createQueue`, `schedule` (bila ada `cron`), dan `work`. Bila registrasi gagal, pg-boss dihentikan lalu error dilempar ulang.
- `apps/api/src/core/jobs/heartbeat.job.ts`: job `system.heartbeat`, cron `*/5 * * * *` (UTC), handler hanya menulis log `heartbeat` dengan `job` dan `jobId`.
- `apps/api/src/core/shutdown.ts`: `createShutdown({ logger, server, boss, closers, exit })` dengan urutan: tutup server (tolak koneksi baru, tunggu request berjalan) → `boss.stop({ graceful: true })` → tutup koneksi lain → `exit`. Langkah gagal dicatat, langkah berikutnya tetap jalan, exit code 1. Sinyal kedua mengembalikan proses shutdown yang sama. `closeServer()` menutup koneksi keep-alive idle setiap 100 ms selama menunggu.
- `apps/api/src/server.ts`: memanggil `startBoss` dengan `RUN_WORKER` dan `heartbeatJob`; gagal start → log `fatal`, tutup koneksi, exit 1. Log `API listening` kini memuat `worker: true/false`. `SIGINT`/`SIGTERM` memakai `createShutdown`.
- Env baru `RUN_WORKER` (`true`/`false`, default `false`) di `env.ts`, `.env.example` (`RUN_WORKER=true` untuk development lokal), dan `test/setup/env.ts` (`false`).
- `pg-boss` 12.36.0 dipasang dengan `-E` (rilis 2026-10-02, lolos `minimumReleaseAge`; `pnpm-workspace.yaml` tidak berubah).

## Keputusan yang diambil sendiri

- **`RUN_WORKER` hanya menerima `true`/`false`.** Nilai lain (`1`, `yes`, `TRUE`, string kosong) membuat server gagal start dengan pesan yang menyebut `RUN_WORKER`, agar salah ketik tidak diam-diam mematikan worker.
- **`.env.example` berisi `RUN_WORKER=true`** agar development lokal sesuai D-05 (pg-boss penuh di proses API). `.env` milik user tidak diubah; tanpa baris itu worker mati.
- **pg-boss memakai pool sendiri** dari `DATABASE_URL`, bukan pool Drizzle: pg-boss butuh koneksi khusus untuk LISTEN/NOTIFY dan menutup pool-nya sendiri saat `stop()`.
- **Fungsi shutdown di `core/shutdown.ts`** dengan dependency yang diteruskan (`server`, `boss`, `closers`, `exit`), sehingga test memanggilnya langsung tanpa sinyal OS. Pada Windows, `SIGTERM` ke child process tidak bisa ditangkap handler, jadi test lewat sinyal tidak bisa diandalkan.
- **Koneksi keep-alive idle ditutup setiap 100 ms selama shutdown.** Ditemukan saat test: `server.close()` baru selesai ~3 detik setelah request terakhir (diukur dengan probe di scratchpad) karena koneksi keep-alive `fetch` tetap terbuka sampai timeout. `closeIdleConnections()` dipanggil berkala sampai server tertutup; request yang masih berjalan tidak diputus.
- **Langkah shutdown yang gagal tidak menghentikan langkah berikutnya**, tetapi membuat exit code 1, agar pool database tetap ditutup walau pg-boss gagal berhenti.
- **Job milik fitur ditaruh di `features/<fitur>/jobs/`**, `core/jobs` hanya untuk job sistem; nama queue `<area>.<aksi>`. Dicatat di `docs/conventions.md`.

Usulan untuk `docs/conventions.md`: sudah ditambahkan (bagian "Job (pg-boss)" dan "Shutdown").
