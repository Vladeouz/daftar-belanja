# T-008 Helper pagination cursor

## Status

Selesai. Branch: `feat/t-008-pagination`.

## Ringkasan

`apps/api/src/core/http/pagination.ts` menyediakan:

- `encodeCursor({ createdAt, id })` / `decodeCursor(cursor)`: base64url dari `createdAt|id`. `decodeCursor` mengembalikan `null` untuk cursor rusak dan hanya menerima bentuk kanonis (decoder base64url Node diam-diam mengabaikan karakter asing). `createdAt` harus ISO 8601 UTC berakhiran `Z` dengan 0–6 digit pecahan, `id` harus UUID.
- `CursorSchema`: string → `{ createdAt, id }`; cursor rusak menjadi issue `custom` `Invalid cursor`, sehingga `defaultHook` menghasilkan `422` dengan `details.cursor`. Di OpenAPI tetap `type: string`.
- `PaginationQuerySchema`: `limit` (coerce, integer, 1–100, default 20) dan `cursor` opsional; bisa di-`extend` untuk filter tambahan.
- `pageSchema(ItemSchema, 'NamaPage')`: respons `{ items, nextCursor }` dengan `nextCursor` nullable, diberi nama komponen OpenAPI.
- `buildPage(rows, limit, positionOf)`: dari `limit + 1` baris membentuk `Page<T>`; `nextCursor` menunjuk item terakhir yang dikembalikan, atau `null` bila tidak ada baris tambahan.
- Konstanta `DEFAULT_PAGE_LIMIT` (20) dan `MAX_PAGE_LIMIT` (100).

## Keputusan yang diambil sendiri

- **`createdAt` di cursor berupa string, bukan `Date`.** PostgreSQL menyimpan `timestamptz` sampai mikrodetik (`defaultNow()`), sedangkan `Date` hanya milidetik. Cursor dari `Date` yang terpotong membuat `(created_at, id) < (cursor)` bernilai salah untuk baris terakhir halaman, sehingga baris itu muncul lagi di halaman berikutnya (duplikat di FR-09). `encodeCursor` tetap menerima `Date` untuk kasus kolom berpresisi milidetik. Cara repository notes mendapatkan nilai presisi penuh (misalnya memilih `created_at` sebagai teks, atau kolom `precision: 3`) diputuskan di T-011.
- **Hanya cursor kanonis yang diterima** (encode ulang harus sama persis), agar `?cursor=xyz` dan cursor yang ditempeli karakter asing ditolak, bukan di-decode sebagian.
- **Kode issue cursor rusak `custom`** dengan pesan `Invalid cursor`, karena berasal dari `ctx.addIssue` Zod; tidak menambah kode baru di luar kode issue Zod (PRD bagian 5).
- **Tanpa `.openapi()` pada `limit`.** Percobaan pertama memberi `.openapi({ type: 'integer' })` dan ternyata menghapus `minimum`, `maximum`, dan `default` dari OpenAPI; tanpa override, zod-openapi sudah menghasilkan `type: integer` beserta batasannya. Dijaga test OpenAPI dan dicatat di conventions.
- **`buildPage` ada di `core/http/pagination.ts`** walaupun bisa dipakai use case: fungsinya murni (tanpa Hono dan Drizzle), jadi tidak melanggar aturan Clean Architecture; satu file untuk semua aturan pagination lebih mudah ditiru.
- **Tidak ada helper kondisi SQL Drizzle** di T-008, karena `core/http` tidak boleh bergantung pada Drizzle dan daftar `files` task ini tidak mencakup `db/`. Kondisi `(created_at, id) < (...)` ditulis di repository T-011.

Usulan untuk `docs/conventions.md`: sudah ditambahkan (bagian Pagination).
