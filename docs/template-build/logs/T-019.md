# T-019 Dockerfile API untuk produksi

## Status

Selesai (2026-10-10). Branch: `chore/t-019-dockerfile-api` (dari `master` setelah T-018 digabung).

## Ringkasan

- Script `build` di `apps/api/package.json`: `tsc -p tsconfig.build.json`, mengompilasi `src/` ke `dist/` dengan struktur yang sama (`dist/server.js`, `dist/db/migrate.js`). `tsconfig.build.json` mewarisi `tsconfig.json`, tetapi hanya `src` dengan `rootDir: src`. Karena kedalaman folder sama, `MIGRATIONS_FOLDER` (`../../drizzle` dari `db/client`) tetap menunjuk `apps/api/drizzle` tanpa perubahan kode.
- `apps/api/Dockerfile` multi-stage di atas `node:24-trixie-slim` (sama dengan image emulator):
  - `base`: `corepack enable` (pnpm dari `packageManager`), salin manifest dan lockfile;
  - `build`: `pnpm install --frozen-lockfile --filter api`, salin `src` dan tsconfig, `pnpm --filter api build`;
  - `prod-deps`: `pnpm install --frozen-lockfile --prod --filter api`;
  - `runtime`: `NODE_ENV=production`, `PORT=3000`, user `node`, isi `/app/node_modules` (virtual store pnpm) + `/app/apps/api/{node_modules,package.json,drizzle,dist}`, `HEALTHCHECK` ke `/health` dengan `fetch` Node, `CMD ["node", "dist/server.js"]`. Migrasi: `node dist/db/migrate.js` sebagai perintah terpisah.
- `.dockerignore` di root berbentuk allowlist: build context hanya berisi manifest, lockfile, `pnpm-workspace.yaml`, tsconfig, `apps/api/src`, dan `apps/api/drizzle` (4,31 kB). `.env` dan `node_modules` Windows tidak pernah ikut.
- README: bagian baru "Image produksi API" (build, migrasi, run, mencoba dengan layanan lokal lewat `host.docker.internal`) dan baris `pnpm --filter api build` di tabel perintah.

`@types/node` dan `@types/pg` ada di image, tetapi bukan sebagai devDependency proyek. Keduanya dependency produksi transitif (`pnpm why --prod`): `@types/pg` ← `drizzle-orm`; `@types/node` ← `@types/jsonwebtoken` ← `jwks-rsa` ← `firebase-admin` dan ← `protobufjs`. Karena itu `pnpm install --prod` tetap memasangnya.

Pemeriksaan tambahan (bukan kriteria):

- `GET /v1/me` tanpa token → `401`; dengan ID token dari Auth Emulator → `200` dan user di-upsert, jadi firebase-admin dan database berjalan dari dalam container.
- `docker inspect` → `health=healthy` setelah start period.
- `docker stop` → log `shutting down` lalu `shutdown complete`, exit code 0 (shutdown bertahap T-009).
- Mode produksi (`NODE_ENV=production` bawaan image, hanya `DATABASE_URL`, `FIREBASE_PROJECT_ID`, `CORS_ORIGINS`): `/health` → `200`, worker dan adapter `none`. Dengan `FIREBASE_AUTH_EMULATOR_HOST` di-set → exit 1 dengan `Must not be set when NODE_ENV=production`.

## Keputusan yang diambil sendiri

- **Dua stage install (`build` dan `prod-deps`), bukan `pnpm deploy`.** `pnpm deploy` menyalin file paket mengikuti aturan publish, dan `dist/` di-ignore Git; perilakunya juga berubah antarversi pnpm. Dengan install `--prod --filter api`, struktur symlink pnpm (`/app/node_modules/.pnpm` + `apps/api/node_modules`) disalin apa adanya. Hasilnya lebih mudah diperiksa.
- **Base `node:24-trixie-slim`**, bukan Alpine: sama dengan image emulator, glibc (aman untuk dependency native transitif firebase-admin/gRPC), dan tetap kecil.
- **pnpm lewat `corepack enable`** agar versinya selalu mengikuti `packageManager`, tanpa versi kedua di Dockerfile.
- **`.dockerignore` allowlist** (`*` lalu `!…`), bukan denylist, agar file sensitif baru tidak ikut secara tidak sengaja. Konsekuensi: file baru yang dibutuhkan build harus ditambahkan di sana.
- **Image menjalankan `node` langsung sebagai PID 1 dengan user `node`**, tanpa init tambahan. `SIGTERM` sampai ke handler shutdown (terbukti exit 0).
- **`HEALTHCHECK` di Dockerfile** memakai `fetch` bawaan Node 24 (image slim tidak punya `curl`).
- **Nama tag contoh `profil-a/api:local`**, mengikuti `profil-a/firebase-emulator:local` di Compose.

Usulan untuk `docs/conventions.md` (T-020), bagian baru "Image produksi API": build dari root dengan `-f apps/api/Dockerfile`; migrasi selalu lewat `node dist/db/migrate.js` sebagai perintah terpisah sebelum server; file baru yang dibutuhkan build ditambahkan ke `.dockerignore`; dependency produksi baru otomatis ikut lewat `pnpm install --prod`.

## Kendala

- **Test flaky `test/unit/server.test.ts`** (juga tercatat di T-018): test itu menjalankan `node --import tsx src/server.ts` lewat `spawnSync`, sementara batas default Vitest 5 dtk. Di sesi ini test itu gagal sekali (5,1 dtk), lalu hijau saat diulang tanpa perubahan apa pun; sebelumnya ada beban dari build Docker. Ini tidak terkait T-019. Perbaikan sudah disarankan sebagai task `fix` terpisah: timeout eksplisit di test itu (misalnya `30_000`, lebih besar dari `timeout: 20_000` milik `spawnSync`). Gejalanya sudah muncul dua kali, jadi sebaiknya dikerjakan sebelum T-020, agar `pnpm check` di CI tidak gagal secara acak.
- Image 476 MB, sebagian besar dari base `node:24-trixie-slim` dan `firebase-admin` beserta dependency gRPC/Firestore-nya (119 MB `node_modules`). Tidak dioptimalkan lebih jauh karena tidak ada target ukuran.
